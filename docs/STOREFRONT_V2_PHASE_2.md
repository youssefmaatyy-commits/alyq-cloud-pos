# ALYQ Cloud POS — Storefront V2 Phase 2 final report

**Date:** 24 September 2026\
**Status:** Phase 2 implemented and validated locally; Phase 3 **not started**.\
**Admin:** `#/online/website?tab=v2` (requires `manage_website`)\
**Public opt-in preview:** `#/store/v2` · `#/store/v2/products` · `#/store/v2/products/:slug-or-id`\
**Scope:** Presentation and website settings only. Legacy `#/store` remains the default storefront.

## Architecture and ownership

1. **Outcome.** A bilingual V2 Customization Studio now edits a typed, persisted V2-only appearance group inside the existing Website Admin. Saved changes affect the opt-in V2 shell; they do not launch another CMS or change checkout, POS, stock or order authority.
2. **Repository hygiene.** Existing dirty tracked and untracked work was inspected and preserved. No clean/reset/revert, unrelated overwrite, deployment, push, pull request or GitHub operation was performed. The pre-existing untracked SQL migration is unrelated and was not touched.
3. **Entry and authorization.** The existing website-management route adds a **STOREFRONT V2** tab. It remains behind the page's existing `manage_website` permission; a cashier cannot open the editor. Public V2 browsing remains unauthenticated.
4. **Single settings document.** The new `WebsiteSettings.storefront_v2` type is a presentation-only group with nullable/inherit defaults. The existing `website_settings` JSONB row, demo localStorage repository, atomic `saveSettings` path, draft/saved state, Save/Discard actions, invalidation notification and media uploader are reused.
5. **Migration decision.** Read-only inspection of the latest identified `website_settings_guard()` in `supabase/migrations/0047_admin_danger_zone.sql` found no top-level JSON key whitelist. This additive, backwards-compatible group does **not** require a migration. No SQL, RLS, RPC or Edge Function was changed.
6. **Read and write safety.** `resolveSettings` fills old documents with V2 defaults and repairs the new group on reads. `sanitizeSettings` rebuilds it from an explicit allowlist on saves; the V2 appearance adapter sanitizes again at rendering. The old SQL guard validates its existing shared fields but **does not** server-validate V2-only keys; the client/rendering boundary is intentional and documented, not presented as a new database guarantee.
7. **Shared versus V2-only ownership.** Shared brand, logos, hero slides, announcement content/mode, cards, badges, footer content, links and the base palette remain in their original Admin tabs. Studio shortcuts lead to those editors instead of copying them. Scope badges distinguish **Legacy + V2** from **V2 only**; background-image, legacy header preset and dark-mode switch exceptions are explicitly labelled **Legacy only**.
8. **Routing and data boundary.** V2 still reads the existing storefront providers and catalogue. `#/store`, its legacy pages, cart, checkout, account, tracking, about and contact are unchanged. V2's new controls only supply scoped presentation tokens and header visibility; the mobile menu retains a route to the existing cart/account even if a header icon is hidden.

## Customization Studio

9. **Draft workflow.** Editing any V2 field updates the existing website draft, not the published shop. One Save validates the whole draft, sanitizes and persists one document; a mistyped V2 hex blocks the entire write rather than silently replacing the last valid colour. Discard still restores the last saved document.
10. **Branding source.** The desktop V2 logo uses the existing shared logo and alternate dark-surface logo; name/wordmark falls back to shared brand values. No V2-only copy of the brand or upload pipeline was created.
11. **Mobile logo and sizes.** An optional V2 phone logo uses `SettingsImageField` and the existing media/URL upload path; clearing it inherits the shared logo. Separate V2-only desktop and phone logo heights are constrained to 20–96px and 20–64px respectively, and the header grows to fit them.
12. **Header presentation.** V2-only header background and text/icon colours are persisted. Sticky position, search/account/cart header icons can inherit shared visibility or use explicit V2 on/off choices; the V2 language switch can be hidden without changing the saved language or legacy storefront.
13. **Page palette.** V2-only overrides cover page background, card surface, main text, muted text, accent and border; unset fields inherit the shared theme or a safe V2 default. Tokens are installed on `.store-v2`, not the document or Admin/POS root.
14. **Buttons.** Background, foreground and rounded/pill/square shape are editable just for V2. Shape inherits the shared button style until overridden; the primary controls, including product actions, consume the scoped tokens.
15. **Badges.** Background, text and square/pill shape can be overridden in V2; whether a badge appears still comes from existing card/badge/product data. No fabricated offer or badge eligibility was introduced.
16. **Hero.** V2 has fallback background/text colours for image-free slides. It continues to use shared slides, desktop/mobile images, titles, links and placement. Image-backed slides enforce a minimum 58% dark scrim so white copy does not disappear when the shared overlay setting is too light; this guard applies only to V2.
17. **Announcements.** Shared visibility, bilingual messages, links, static/rotate/scroll mode and interval remain the source of truth. V2-only bar/background text colours inherit these settings until overridden. Links still pass the existing safe-route adapter.
18. **Scrolling ticker and motion.** V2 `scroll` mode now animates a seamless LTR/RTL two-copy ticker at the shared, clamped cadence. The duplicate is aria-hidden and non-interactive; animation pauses on hover or keyboard focus. With `prefers-reduced-motion: reduce`, animation stops, the duplicate disappears and **all** configured messages remain readable in a wrapped static layout. Timed rotation also stops under reduced motion.
19. **Footer.** Background, text and link colours have V2-only overrides. Brand description, newsletter behaviour, social/contact/policy links and copyright remain shared and still use safe destinations; no newsletter endpoint was invented.
20. **Typography.** Body and display selectors offer curated, locally available stacks only, with Arabic serif/sans fallbacks. No free-form font family, CSS injection, arbitrary web-font URL or external font request is accepted. Arabic RTL headings/body use corresponding readable fallback stacks.
21. **Mobile grid parity.** Below 640px, V2 now honours a V2-only one/two-column choice or inherits the shared `product_card.mobile_columns`, safely capped at 2 if a legacy setting is 3. Tablet still uses three; desktop consumes the existing shared desktop column count and card-gap controls.
22. **Colour input and contrast.** Each V2 override has a colour picker, editable validated hex field, an inherited-value hint and a per-field Clear action. Only opaque `#RGB`/`#RRGGBB` is accepted for V2 overrides; transparent values cannot undermine contrast calculations. Effective foregrounds are checked against their actual background (including card surfaces, hero, buttons, badges, header, announcement and footer) and fall back to accessible ink at **≥4.5:1**. The Studio shows effective pair ratios and flags auto-adjustment without destroying the editable saved request.
23. **Media and CSS safety.** The same `safeImageField` URL policy validates a V2 mobile logo; the existing remote-save converter promotes only bundled `/brand/…` media to the storefront origin. Unsupported enums, unsafe URLs, unknown JSON keys, out-of-range sizes and invalid CSS colour values are discarded on reads/saves/render; raw user CSS is not supported.
24. **Preview honesty.** The new Admin V2 draft appearance sample uses the same adapter/CSS tokens, real shared hero and published catalogue images, and EN/AR plus phone/desktop switches. It is inert, representative and clearly labelled **not the full responsive store**; the pre-existing legacy fragment is separately labelled **not V2**. An **Open saved V2 site** link opens the actual route, with a same-tab fallback, and warns that unsaved draft changes will not appear there.
25. **Safe reset.** A two-step **Reset V2 appearance** action replaces only `storefront_v2` in the draft with its defaults. It does not delete shared content, uploaded files, legacy styling or any commerce data; Save is still required. Per-colour Clear restores inheritance without resetting the other overrides.
26. **Localization and keyboard use.** Studio labels, scope guidance, warnings and preview instructions are paired in EN/AR. New fields have programmatic labels, invalid state/alerts are exposed, the preview is an inert labelled group, and the public ticker respects focus and reduced-motion preferences. The existing skip link, RTL layout and mobile drawer continue to work.

## Verification and limits

27. **Static/production checks.** `npm run typecheck`, `npm run build` and `git diff --check` passed. `npm run lint` passed with **0 errors and 34 existing worktree warnings**; targeted lint for the touched V2/Admin/settings files passed with no output. No warnings were represented as an entirely warning-free lint run.
28. **Logic and DOM regressions.** `npm run test` passed **46/46 suites**, including **10/10 focused V2 logic tests** covering old JSON, allowlisting, URL conversion, mobile columns, contrasts and legacy-theme isolation. Selected `npm run test:e2e` passed **11/11 suites** covering legacy store/checkout/POS, existing website editor/theme, Admin/navigation/branding, V2 Phase 1 and the new Phase 2 Studio (**21 assertions**, plus a separate fresh-process reload). Each suite uses its own demo state.
29. **Real-browser V2 matrix.** The earlier Phase 1 Chromium baseline passed **60/60** home/catalogue/PDP cases and **20/20** exact-variant cases. The new Phase 2 suite covered the same ten widths (320, 360, 375, 390, 414, 768, 1024, 1280, 1440 and 1920px) in EN/LTR and AR/RTL and passed **40/40** configured home/catalogue cases, **20/20** configured exact-variant PDP cases and **10/10** two-column phone checks. It verified saved Admin changes after browser reload, ticker direction/focus/reduced motion, logo bounds, grid columns, absence of horizontal overflow and no browser console/network errors. Admin draft preview fit 320/390/768/1440px and switched desktop/Arabic independently. Ignored screenshots live in `coverage/visual-v2-phase2/` during this session.
30. **Saved-state proof.** In both jsdom (fresh process) and Chromium (real reload), a saved V2 background, header, logo, shape, font and grid reached the opt-in route. The same saved document retained shared announcement/card/theme values. V2 reset was saved and verified to restore only the V2 group. Legacy `#/store` and POS still lacked V2 tokens; no alternate cart or inventory path was exercised or added.
31. **Honest limitations.** The manual/browser runs used **demo-mode persistence**, not a production Supabase account; the Supabase save converter was unit-checked and the SQL guard inspected read-only, but a live production upsert was not attempted. Direct SQL writers bypassing the client can store malformed V2 keys; V2's renderer rejects them, but the old server guard itself does not enforce the new group. The draft sample is appearance-only and cannot reproduce full-site responsive behaviour or commerce; use **Open saved V2 site** after Save for that. This is not an exhaustive accessibility certification or production-order test.
32. **Stop point.** Phase 2 is complete locally. No Phase 3 page migration, canonical-route switch, cart/checkout redesign, new commerce service, database migration, deployment or GitHub publication was started. V2 remains opt-in until separately authorized work changes that boundary.
